> **Important Batching Finding (`classifier.py:742-747`, `regressor.py:553-558`)**: With default `n_estimators=8` and `norm_methods=["none", "power"]`, `EnsembleGenerator.transform(X)` returns a 2-entry `OrderedDict` (`"none"` with shape `(4, T, H)` and `"power"` with shape `(4, T, H)`). Upstream loops over `data.items()`, launching **two separate `B=4` forward passes** instead of one `B=8` pass! ### 1.3 End-to-End Forward Pipeline (`ColEmbedding -> RowInteraction -> ICL Learning`)

Given preprocessed ensemble batch `X` of shape `(B, T, H)` (where `T = T_train + T_test` rows, `H` active features after `UniqueFeatureFilter`, and all input `NaN`s already imputed on CPU via `TransformToNumerical` — `SimpleImputer(strategy="mean")` for continuous, `-1` category for categorical) and `y_train` of shape `(B, T_train)`:

1. **Stage 1 — Distribution-Aware Column-wise Embedding (`ColEmbedding`, $\mathcal{O}(B \cdot H \cdot T \cdot m)$ with $m=128$)**:
   - **Circular Feature Grouping (`embedding.py:234-236`)**: Each column $j \in [0, H)$ is grouped with circular neighbors $(j + 2^0) \bmod H$, $(j + 2^1) \bmod H$, $(j + 2^2) \bmod H$, producing `(B, T, G, 3)` with `G = H`.
   - **CLS Slot Padding & Projection (`embedding.py:595-610`)**: Pads `C = 4` leading slots along `G` with `-100.0` (`skip_value`), transposes to `(B, G+4, T, 3)`, applies `SkippableLinear(3, 128)` $\rightarrow$ `src` `(B, G+4, T, 128)`, and adds `y_encoder(y_train)` (`(B, 1, T_train, 128)`) to `src[:, :, :T_train, :]`.
   - **3× Induced Self-Attention (`SetTransformer`, `layers.py:625-652`)**: Columns are processed **completely independently** along flattened batch `B * (G+4)`:
     - `multihead_attn1` (with `QASSMaxMLP` scaled by $\log T_{\text{train}}$): `ind_vectors` `(128, 128)` query **only** training rows `src[..., :T_train, :]` $\rightarrow$ `hidden` `(B, G+4, 128, 128)` (preventing test-set distribution leakage).
     - `multihead_attn2` (no SSMax): All `T` rows `src` independently query the `128` inducing vectors `hidden` $\rightarrow$ `(B, G+4, T, 128)`.
   - Transposes back to `embeddings` of shape `(B, T, G+4, 128)`.

2. **Stage 2 — RoPE Row-wise Feature Interaction (`RowInteraction`, $\mathcal{O}(B \cdot T \cdot (H+4)^2)$)**:
   - Overwrites the 4 leading dummy slots `embeddings[:, :, :4, :]` with learnable `cls_tokens` `(4, 128)`.
   - Runs **Blocks 0 & 1** of `tf_row` (`Encoder`, `d=128`, `nhead=8`, non-interleaved RoPE `theta=100000`, `ssmax=False`) as full self-attention over all `G+4` tokens independently for every row in `B * T`.
   - Runs **Block 2 (last block)** as cross-attention with queries `q = embeddings[:, :, :4, :]` (`4` CLS tokens) attending to keys/values `k = v = embeddings` (`G+4` tokens), applies `out_ln` (`LayerNorm(128)`), and flattens `(4, 128)` $\rightarrow$ row representations `R` of shape `(B, T, 512)`.

3. **Stage 3 — Dataset-wise In-Context Learning (`ICLearning`, $\mathcal{O}(B \cdot T \cdot T_{\text{train}})$)**:
   - Injects training labels into the context prefix: `R[:, :T_train, :] += y_encoder(y_train)` (`(B, T_train, 512)`).
   - Runs **12× `MultiheadAttentionBlock`s** (`d=512`, `nhead=8`, `head_dim=64`, `QASSMaxMLP` scaled by $\log T_{\text{train}}$): in **every** block (`layers.py:437`), queries are the full sequence `q = R` (`T = T_train + T_test`), while keys and values are **strictly** the training slice `k = v = R[:, :T_train, :]`! Test rows **never** attend to other test rows; test rows are processed completely independently of one another!
   - Applies final `ln` (`LayerNorm(512)`) and 2-layer `decoder` (`512 -> 1024 -> out_dim`) and slices `out[:, T_train:, :num_classes]` (classification logits, `num_classes <= 10`) or `out[:, T_train:, :]` (`999` quantiles for regression, sorted via `torch.sort(..., dim=-1).values` and averaged for point mean prediction).
   - **Many-class (`num_classes > 10`)**: `ColEmbedding` decomposes labels via balanced mixed-radix digits ($\le 10$ per digit) and averages `tf_col` outputs; `ICLearning` fits a recursive `ClassNode` tree on `R[:T_train]` where each internal/leaf node solves a $\le 10$-way subproblem.

## 3. Detailed TorchTPU Engineering Designs (Phases 1.3 & 1.4)

### 3.1 Design (a): Eager `torch.device("tpu")` (`fp32` & `bf16`) + `kv_cache` Support

#### 1. Device Selection & Validation (`src/tabicl/_torch_devices.py`, `src/tabicl/_sklearn/base.py`)
- **Current behavior**:
  - `resolve_torch_device("tpu")` (`_torch_devices.py:85-108`) calls `torch.device("tpu")`, which already succeeds when `torch_tpu` registers the `"tpu"` backend with PyTorch.
  - However, `DEFAULT_DEVICE_PREFERENCE = ("cuda", "xpu", "mps", "cpu")` (`_torch_devices.py:14`) omits `"tpu"`, so `TabICLClassifier(device=None)` silently falls back to `"cpu"` on a TPU v7x node!
- **Planned change**:
  - Update `DEFAULT_DEVICE_PREFERENCE = ("tpu", "cuda", "xpu", "mps", "cpu")`.
  - Verify `_is_device_backend_available("tpu")` checks `getattr(torch, "tpu", None)` and `torch.tpu.is_available()`.
  - Support both `"tpu"` and indexed `"tpu:0"` .. `"tpu:3"` (matching `devices_match` in `inference.py:26-41`, where `torch.device("tpu")` index `None` matches `tpu:0`).

#### 2. Eliminating `InferenceManager` Silent CPU-Offload & `batch_size=1` Collapse on TPU (`src/tabicl/_model/inference.py`)
- **Root cause**:
  - `InferenceManager.__call__` (`inference.py:1297`) treats every non-CPU `exe_device` as an accelerator requiring dynamic memory-probed chunking.
  - `get_available_gpu_memory()` (`inference.py:895-943`) calls `backend.synchronize()`, `backend.empty_cache()`, and looks for `torch.tpu.mem_get_info`. When `torch_tpu` does not expose CUDA-style `mem_get_info` (or returns `(0, 0)`), `gpu_mem` evaluates to `0.0`.
  - `gpu_mem == 0.0` triggers a **triple failure**:
    1. `estimate_safe_batch_size()` (`inference.py:988`) returns `batch_size = 1` (running 1 column per step in `ColEmbedding` and 1 row per step in `RowInteraction`!).
    2. `_resolve_offload_mode()` (`inference.py:1098-1125`) checks `has_gpu = gpu_free_mb > 0` (`False`) and **overrides even explicit `offload=False` (`OffloadMode.GPU`) to `OffloadMode.CPU`**!
    3. `_allocate_output_buffer()` (`inference.py:1155`) allocates CPU tensors with `pin_memory=True` (invoking CUDA host-pinned memory), while `AsyncCopyManager` (`inference.py:459`) emits a `RuntimeWarning` and performs synchronous `.cpu()` copies after every single `batch_size=1` step!
- **Planned change**:
  - Add a dedicated TPU HBM query helper `_get_tpu_free_memory_mb(device)`:
    - Query `torch.tpu.mem_get_info(device)` if available in `torch_tpu==0.2.0`; else fall back to `(TPU_HBM_TOTAL_MB - allocated_mb)` using `torch.tpu.memory_allocated(device)` with conservative default `TPU_HBM_TOTAL_MB = 96_000.0` (overrideable via `TABICL_TPU_HBM_MB` env var; TPU v7x has ample HBM per chip).
    - **Never** call `backend.synchronize()` or `backend.empty_cache()` during routine TPU forward passes (`inference.py:916-920`), as those stall the asynchronous TorchTPU execution pipeline!
  - In `_allocate_output_buffer()` and `PinnedBufferPool`: set `use_pinned = (self.exe_device.type == "cuda")`, never `True` on `"tpu"`.
  - Add a clean device-resident fast path (`exe_device.type == "tpu"` with `offload_mode in ("auto", False, "gpu")` when estimated peak activation fits in TPU HBM): execute `_run_forward` directly on TPU HBM in a single unsplit call without `/proc/self/cgroup` reads or `OrderedDict` slicing.

#### 3. Precision & AMP (`fp32` and `bf16`) on `torch.device("tpu")`
- **Strict Rule**: On TPU v7x, **never** use `torch.float16` and **never** use `torch.GradScaler`.
- **Eager `fp32` mode (`use_amp=False`)**:
  - Keep model parameters in `torch.float32` (default checkpoint dtype).
  - Ensure `torch.backends.fp32_precision` / matmul precision on `torch_tpu` uses high/IEEE or default TPU fp32 accumulation as configured, with `autocast` disabled.
- **Eager `bf16` AMP mode (`use_amp=True` or `"auto"`)**:
  - Fix `inference.py:1230`:
    ```python
    if self.use_amp:
        amp_dtype = torch.bfloat16 if self.exe_device.type == "tpu" else None
        with torch.autocast(device_type=self.exe_device.type, dtype=amp_dtype):
            return model(**inputs, **kwargs)
    ```
  - Fix `rope.py:56, 287, 298, 401` (**RoPE `float32` guard**):
    - Replace `@torch.autocast("cuda", enabled=False)` with an explicit `with torch.autocast(device_type=t.device.type, enabled=False):` context around `get_seq_pos(..., dtype=torch.float32)`, `einsum`, and `freqs.cos()` / `freqs.sin()`, casting back `.to(t.dtype)` at the end of `apply_rotary_emb`. This prevents both `bf16` integer position rounding above `256` features and `bf16` trigonometric phase drift.
  - Fix `layers.py:89` (`OneHotAndLinear.forward`):
    - Change `F.linear(one_hot.float(), self.weight, self.bias)` $\rightarrow$ `F.linear(one_hot.to(self.weight.dtype), self.weight, self.bias)` so both `autocast("tpu", dtype=torch.bfloat16)` (with `fp32` master weights) and pure `model.to(torch.bfloat16)` modes work seamlessly.
  - Note on `_resolve_amp_fa3` (`base.py:100-141`):
    - Upstream disables `use_amp="auto"` on tiny datasets (`n_samples < 1024 and n_features < 60`). Explicit `use_amp=True` forces `bf16` across all dataset sizes; explicit `use_amp=False` forces `fp32` across all dataset sizes. `use_fa3` resolves to `False` whenever `device_type != "cuda"`, cleanly routing `attention.py:128` to `F.scaled_dot_product_attention`.

#### 4. `kv_cache` Support on TPU (`kv_cache=True` / `"kv"` and `kv_cache="repr"`)
- **Lifecycle**:
  - `fit(X_train, y_train)` calls `_build_kv_cache()` (`classifier.py:530`, `regressor.py:448`), running `TabICL.forward_with_cache(..., use_cache=False, store_cache=True)` to populate `self.model_kv_cache_[norm_method]`:
    - `cache_mode="kv"` (`kv_cache=True`): caches `col_cache` (`3` ISAB blocks × K & V of `multihead_attn2`, each `(B, G+4, 8, 128, 16)`) and `icl_cache` (`12` ICL blocks × K & V over `T_train`, each `(B, 8, T_train, 64)`).
    - `cache_mode="repr"` (`kv_cache="repr"`): caches `col_cache` + `row_repr` (`(B, T_train, 512)` after `RowInteraction` + `y_encoder`).
  - `predict(X_test)` / `predict_proba(X_test)` calls `_batch_forward_with_cache()`, running `TabICL.forward_with_cache(X_test, ..., use_cache=True, store_cache=False)` in $\mathcal{O}(T_{\text{test}} \cdot H^2 + T_{\text{test}} \cdot T_{\text{train}})$ time!
- **Required TPU Fixes for `kv_cache`**:
  1. **Eliminate host syncs in `forward_with_cache`**: Pass `num_classes=self.n_classes_` (`0` for regression) from `TabICLClassifier`/`TabICLRegressor` into `TabICL.forward_with_cache` $\rightarrow$ `ColEmbedding.forward_with_cache` & `ICLearning.forward_with_cache`, removing `tabicl.py:726` (`torch.unique`), `embedding.py:850` (`.item()`), `learning.py:800` (`torch.unique`), and `layers.py:787-795` (`skip_mask.all()`/`.any()`).
  2. **Consistent Cache Dtype (`bf16` vs `fp32`)**:
     - When `use_amp=True` on TPU, `k_proj` and `v_proj` computed inside `autocast("tpu", dtype=torch.bfloat16)` are naturally `torch.bfloat16` (cutting `icl_cache` HBM usage in half: e.g., at `B=8, T_train=50000`, `12 * 2 * 8 * 8 * 50000 * 64 * 2 B = 9.83 GB` in `bf16` vs `19.66 GB` in `fp32`!).
     - When `use_amp=False`, `k_proj` and `v_proj` are stored in `torch.float32`.
     - **Defensive SDPA guard (`attention.py:252`)**: Always cast `k = cached_kv.key.to(q.dtype); v = cached_kv.value.to(q.dtype)` so cross-device `save()`/`load()` or `use_amp="auto"` threshold crossings between `fit(X_train)` and `predict(X_test)` **never** crash `F.scaled_dot_product_attention`! (Note: in `classifier.py:648`, `_resolve_amp_fa3` during `_batch_forward_with_cache` passes `Xs.shape[1]` = `T_test` instead of `T_train`! So a large `T_train = 5000` built in `bf16` followed by a tiny `T_test = 10` batch with `use_amp="auto"` resolves `use_amp = False` (`q` in `fp32`) while `cached_kv` is `bf16` — which **crashes upstream today** without our `k.to(q.dtype)` fix!!).
     - **`prepare_repr_cache` fix (`tabicl.py:762`, `learning.py:579`)**: Wrap `prepare_repr_cache` in the active `autocast` context (or cast `Ry_train` to `representations.dtype`) so `"repr"` caches stay `bfloat16` when AMP is enabled.
     - **`_move_cache_to_device` (`base.py:178-210`)**: Cast loaded caches to `torch.bfloat16` when `device_.type == "tpu"` and `use_amp=True`, and upcast to `torch.float32` when `use_amp=False`.

### 3.2 Design (b): Zero-Graph-Break `torch.compile` Forward Wrapper

To achieve `fullgraph=True` compilation on TorchTPU with **zero graph breaks**, **zero host-device syncs (`aten._local_scalar_dense`)**, and **zero dynamic-shape ops (`aten.nonzero` / `aten.unique`)**, we introduce a clean functional module / wrapper `TorchTPUTabICLForward(nn.Module)` wrapping the existing `TabICL` parameter tensors without altering checkpoint state-dict keys:

1. **Zero `.item()` / `torch.unique()` on Target Labels**:
   - Standard path (`self.max_classes == 0` or `num_classes <= 10`): **Zero** inspection of `y_train` values on device. `OneHotAndLinear(10, D)` always one-hot encodes into fixed width `max_classes = 10` (`F.one_hot(y_train.long().clamp(0, 9), 10)`). The compiled graph always outputs fixed last-dimension `out_dim` (`10` for classifier, `999` for regressor). Slicing `out[..., :num_classes]` happens **outside** (or after) the compiled graph using CPU `self.n_classes_`, so changing `num_classes` between `2` and `10` **does not even trigger recompilation**!
   - Many-class path (`num_classes > 10`): Mixed-radix base computation (`_compute_mixed_radix_bases`) and hierarchical `ClassNode` tree construction (`_fit_node` / `_label_encoding`) run their index book-keeping on CPU (`y_train_np`), invoking the compiled 10-class TPU sub-graphs (`col_embed_compiled`, `row_interact_compiled`, `icl_predict_compiled`) as static-shape leaf kernels.

2. **Eliminate `-100.0` `skip_value` Masking & `aten.nonzero` Compaction (`ColEmbedding` + `RowInteraction`)**:
   - **Mathematical observation**: Upstream `ColEmbedding` pads 4 dummy feature groups filled with `-100.0`, runs `SkippableLinear` (`if skip_mask.any()`) and 3× `InducedSelfAttentionBlock` (`if skip_mask.any(): out[~skip_mask] = ...`), and then `RowInteraction` **immediately overwrites** `embeddings[:, :, :4, :] = cls_tokens` (`interaction.py:248`)! Because `ColEmbedding` processes every group independently along flattened batch `B * G` (zero cross-group interaction), the 4 dummy `-100.0` groups have **zero mathematical effect** on the `G` real feature embeddings!
   - **Zero-graph-break replacement**:
     - Run `in_linear` (`F.linear(X_grouped, weight, bias)`) + `y_emb` addition + all 3 `InducedSelfAttentionBlock.induced_attention` layers directly on `(B, G, T, 3)` **without** `-100.0` dummy slots, `skip_mask.any()`, or `src[~skip_mask]`!
     - In `RowInteraction`, prepend `cls_tokens` functionally via `embeddings = torch.cat([cls_tokens.expand(B, T, 4, E), feat_embeddings], dim=2)` (replacing in-place `embeddings[:, :, :4] = cls_tokens` as well!).
     - This eliminates **all 7 data-dependent branches** (`1` in `SkippableLinear` + `2 × 3 = 6` in `SetTransformer`), **all 4 `aten.nonzero` boolean index compactions**, and saves `4 / (G + 4)` FLOPs in `ColEmbedding`, while producing **bit-for-bit identical** tensors entering `RowInteraction`!

3. **Pure Functional RoPE & Device-Tensor SSMax**:
   - `RotaryEmbedding`: compute `seq = torch.arange(seq_len, device=t.device, dtype=torch.float32)` and `freqs = torch.outer(seq, self.freqs.float())` functionally without `tmp_store` / `register_buffer` mutations or `einops` string parsing.
   - `QASSMaxMLP`: accept `log_n: Tensor` of shape `(1, 1)` on device (computed as `torch.log(n_train_t.to(torch.float32).clamp(min=1.0)).to(q.dtype).view(1, 1)`) instead of Python `math.log(n)` + `torch.tensor(...)`.

4. **Zero-Sync Regression Post-Processing (`TabICLRegressor`)**:
   - Replace `QuantileDistribution._setup_spline` `.item()` calls (`quantile_dist.py:604-605`) with Python float constants `1.0 / (num_quantiles + 1)` and `num_quantiles / (num_quantiles + 1)`.
   - Fast-path `output_type="mean"` (`torch.sort(raw_quantiles, dim=-1).values.mean(dim=-1)`) and `output_type="median"` (`torch.sort(raw_quantiles, dim=-1).values[..., num_quantiles // 2]`) inside the compiled TPU graph itself! That reduces regressor D2H transfer volume by **999×** (`(B, T_test)` instead of `(B, T_test, 999)`) when only point predictions are requested!

5. **Compilation Entrypoint**:
   - Compile with `torch.compile(forward_fn, fullgraph=True, dynamic=False)` (using TorchTPU's OpenXLA Inductor/PJRT backend on `torch.device("tpu")`), keyed by static bucket `(B_bucket, T_bucket, H_bucket, amp_enabled, mode)`.
   - Bypass `InferenceManager`, `flash_attn3_toggle`, `psutil`, and `_cgroup_memory_headroom` completely.

### 3.3 Design (c): Exact Masked Shape-Bucketing (`n_rows`, `n_features`, `n_estimators`)

#### 1. Bucket Grids

To bound XLA compilation count on TPU v7x while avoiding excessive padding overhead, inputs `(B_real, T_real, H_real)` (with `T_real = n_train + n_test`) are bucketed via `next_bucket(val, grid)` to the smallest bucket $\ge \text{val}$:

- **`B_bucket` (`n_estimators` batch)**: `{1, 4, 8, 16, 32}`
  - Concatenate ensemble members across `norm_methods` (`"none"` + `"power"`) before bucketing so default `n_estimators = 8` maps directly to `B_bucket = 8` in **1 call** (0% batch padding!). If `B_real > 32`, chunk into multiples of `32` plus tail bucket.
- **`H_bucket` (`n_features` after `UniqueFeatureFilter`)**: `{16, 32, 64, 128, 256, 512}`
  - Covers TabICLv2's entire pre-training regime (`1..100` features) and wide benchmarks up to `512` features (if `H_real > 512`, round up to next power of 2).
- **`T_bucket` (`n_rows = n_train + n_test`)**: `{1024, 2048, 4096, 8192, 16384, 32768, 65536}`
  - Covers small to large TabArena / TALENT tables (if `T_real > 65536`, chunk `X_test` across multiple calls of size `65536 - n_train`, or use `kv_cache=True` with chunked `T_test_bucket`!).

> **Key Design Property — Zero Recompilation Within a Bucket**: All dataset-specific counts `(n_train, H_real)` are passed into the compiled graph as **fixed-shape scalar/1D device tensors**, NOT Python `int` slice bounds! Consequently, two datasets with `(n_train=612, n_test=188, H=19, C=3)` and `(n_train=790, n_test=150, H=29, C=8)` both map to `(B=8, T=1024, H=32)` and execute the **exact same compiled TPU HLO binary** with **zero recompilation**!

#### 2. Stage-by-Stage Mathematical Equivalence Construction & Proof

Let `B_real <= B_bucket`, `1 <= n_train`, `1 <= n_test`, `T_real = n_train + n_test <= T_bucket`, and `1 <= H_real <= H_bucket`.

##### Step A — Host/Device Tensor Packing & Mask Tensors (Static Shapes)
1. **Batch axis (`B_real -> B_bucket`)**:
   - Pad `X` along dim `0` from `B_real` to `B_bucket` by replicating slice `0` (`X[0:1]`), and similarly `y` (`y[0:1]`).
   - *Equivalence*: Every op in `ColEmbedding`, `RowInteraction`, and `ICLearning` treats dim `0` (`B`) as an independent batch dimension with zero cross-batch reductions or normalizations. Thus `out[:B_real]` is bit-for-bit invariant to `B_bucket`.
2. **Feature Circular Grouping (`H_real -> H_bucket`) — Critical Subtlety!**:
   - In TabICLv2 (`col_feature_group="same"`, `size=3`), unpadded `ColEmbedding.feature_grouping` computes circular indices `(j + 2**i) % H_real` for `j in 0 .. H_real - 1`.
   - **Trap avoided**: If `X` were naively zero-padded to `H_bucket` *before* circular indexing, features `H_real - 4 .. H_real - 1` would wrap into padded zeros (`j + 2**i < H_bucket`) instead of wrapping modulo `H_real`!
   - **Exact solution**: Pass `X_padded` of shape `(B_bucket, T_bucket, H_bucket)` (real features in `0 .. H_real - 1`, zeros in `H_real .. H_bucket - 1`) and scalar int64 tensor `H_real_t` (`shape=()`). Inside the compiled graph:
     ```python
     idxs = torch.arange(H_bucket, device=X.device, dtype=torch.long)
     safe_idxs = torch.where(idxs < H_real_t, idxs, 0)
     grouped = torch.stack(
         [
             torch.gather(
                 X,
                 dim=2,
                 index=((safe_idxs + (1 << i)) % H_real_t).view(1, 1, H_bucket).expand(B_bucket, T_bucket, H_bucket),
             )
             for i in range(3)
         ],
         dim=-1,
     )  # Static shape: (B_bucket, T_bucket, H_bucket, 3)
     ```
     For every real feature `j < H_real`, `((safe_idxs[j] + 2**i) % H_real_t) == (j + 2**i) % H_real < H_real`, gathering exclusively from real unpadded columns!
3. **Row Packing & Masks (`n_train, n_test -> T_bucket`)**:
   - Pack rows as `[0 .. n_train - 1]` = `X_train`, `[n_train .. n_train + n_test - 1]` = `X_test`, `[n_train + n_test .. T_bucket - 1]` = `0.0` (or replicate `X_test[0]`).
   - Pack `y_padded` of static shape `(B_bucket, T_bucket)` with `y_train` in `[0 .. n_train - 1]` and `0` in `[n_train .. T_bucket - 1]`.
   - Construct static-shape mask & SSMax scale tensors on device from scalar int64 `n_train_t` and `H_real_t`:
     - `row_idx = torch.arange(T_bucket, device=X.device)` $\rightarrow$ `train_mask = (row_idx < n_train_t)` of shape `(T_bucket,)` (`bool`).
     - `train_attn_mask = torch.where(train_mask, 0.0, float("-inf")).to(compute_dtype).view(1, 1, 1, T_bucket)` — broadcastable `(1, 1, 1, T_bucket)` additive float mask!
     - `log_n_train = torch.log(n_train_t.to(torch.float32).clamp(min=1.0)).to(compute_dtype).view(1, 1)` — static `(1, 1)` tensor!
     - `feat_idx = torch.arange(4 + H_bucket, device=X.device)` $\rightarrow$ `feat_valid = (feat_idx < (4 + H_real_t))` $\rightarrow$ `feat_attn_mask = torch.where(feat_valid, 0.0, float("-inf")).to(compute_dtype).view(1, 1, 1, 4 + H_bucket)` — broadcastable `(1, 1, 1, 4 + H_bucket)` additive float mask!

##### Step B — Stage 1 (`ColEmbedding`) Exactness on Unpadded Entries
- Linear projection `src = in_linear(grouped.transpose(1, 2))` has shape `(B_bucket, H_bucket, T_bucket, 128)` (pointwise per `(b, h, t)`).
- Masked target injection:
  ```python
  y_emb = y_encoder(y_padded)  # (B_bucket, T_bucket, 128)
  src = src + torch.where(train_mask.view(1, 1, T_bucket, 1), y_emb.unsqueeze(1), 0.0)
  ```
  - For `t < n_train`: adds exact `y_encoder(y_train[:, t])`.
  - For `n_train <= t < n_train + n_test`: adds `0.0` (exact match to unpadded `src[..., :train_size, :] += y_emb`).
- In each of the 3 ISAB blocks:
  1. `multihead_attn1`: queries `ind_vectors` `(B_bucket * H_bucket, 8, 128, 16)` attend to full `src` `(B_bucket * H_bucket, 8, T_bucket, 16)` with `attn_mask = train_attn_mask` `(1, 1, 1, T_bucket)` and `ssmax_layer(q, log_n_override=log_n_train)`.
     - All keys at `t >= n_train` (both test rows and padded rows) receive `-inf` before softmax ($e^{-\infty} = 0$), and `n_train >= 1` guarantees at least one `0.0` key so softmax never sees all-`-inf` (`NaN`-free!).
     - `QASSMaxMLP` receives exact $\log(n_{\text{train}})$ rather than $\log(T_{\text{bucket}})$.
     - LayerNorm and FFN are row-wise over the `128` inducing points. Thus `hidden` `(B_bucket, H_bucket, 128, 128)` is **exact** for every `h < H_real`!
  2. `multihead_attn2`: queries `src` (`T_bucket` rows) attend to `hidden` (`128` inducing vectors, `attn_mask = None`, `ssmax = None`). Because queries do not interact with each other across `T_bucket`, `out[:, h, t, :]` is **exact** for all `h < H_real` and all `t < n_train + n_test`!

##### Step C — Stage 2 (`RowInteraction`) Exactness on Unpadded Entries
- Prepend learnable `cls_tokens`: `emb = torch.cat([cls_tokens.expand(B_bucket, T_bucket, 4, 128), col_out.transpose(1, 2)], dim=2)` of shape `(B_bucket, T_bucket, 4 + H_bucket, 128)`.
- Every row `(b, t)` is processed **independently** in `RowInteraction` (`B_bucket * T_bucket` flattened batch; padded rows `t >= n_train + n_test` cannot affect real rows `t < n_train + n_test`).
- Within each row:
  - RoPE positions are `[0, 1, 2, 3]` for CLS tokens and `[4, ..., 4 + H_real - 1]` for real features — identical to unpadded `[0 .. 4 + H_real - 1]` because padded features sit at the tail `[4 + H_real .. 4 + H_bucket - 1]`.
  - In Blocks 0, 1, and Block 2 (`q = emb[..., :4, :]`), `F.scaled_dot_product_attention` receives `attn_mask = feat_attn_mask` `(1, 1, 1, 4 + H_bucket)`.
  - Keys `>= 4 + H_real` receive `-inf` ($e^{-\infty} = 0$), while `4 + H_real >= 5` valid keys (`0.0`) guarantee `NaN`-free softmax even for unused padded query slots in Blocks 0–1!
  - `RowInteraction` has `ssmax = False`, and Pre-LN + FFN + `out_ln` operate per-token along `E = 128`.
  - Therefore `R[:, t, :]` `(B_bucket, T_bucket, 512)` is **exact** for every real row `t < n_train + n_test`!

##### Step D — Stage 3 (`ICLearning`) Exactness on Unpadded Entries
- Masked label injection:
  ```python
  R = R + torch.where(train_mask.view(1, T_bucket, 1), icl_y_encoder(y_padded), 0.0)
  ```
  - Exact for `t < n_train` (`R_train + y_emb`) and `n_train <= t < n_train + n_test` (`R_test + 0`).
- In each of the 12 `tf_icl` blocks:
  - Queries `q` (`T_bucket`) attend to keys/values `k, v` (`T_bucket`) with `attn_mask = train_attn_mask` `(1, 1, 1, T_bucket)` and `ssmax_layer(q, log_n_override=log_n_train)`.
  - Keys `t >= n_train` (both real test rows and padded tail rows!) receive `-inf`, restricting attention strictly to training context `0 .. n_train - 1` (`n_train >= 1` ensures `NaN`-free softmax for all queries, including padded tail queries).
  - `QASSMaxMLP` scales queries using exact $\log(n_{\text{train}})$.
  - Pre-LN, residual connections, FFN, final `ln`, and 2-layer `decoder` are strictly pointwise across `T_bucket`.
- Host/caller slices `out[:B_real, n_train : n_train + n_test, :num_classes]` (classifier) or `out[:B_real, n_train : n_train + n_test, :]` (regressor).
- **Conclusion**: Every unpadded output element $(\text{estimator } b < B_{\text{real}}, \text{test row } t \in [n_{\text{train}}, n_{\text{train}} + n_{\text{test}}), \text{output } c)$ is **mathematically identical** to unpadded eager execution (up to standard floating-point associativity $\sim 10^{-6}$ in `fp32` / $\sim 10^{-3}$ in `bf16`).

#### 3. Masked Shape-Bucketing with `kv_cache=True`
- **`fit(X_train, y_train)` (Context Prefill)**:
  - Bucket `(B_real, n_train, H_real)` $\rightarrow$ `(B_bucket, T_train_bucket, H_bucket)`.
  - Store `TabICLCache` on TPU HBM (`bf16` when `use_amp=True`, `fp32` when `use_amp=False`) with static shapes:
    - `col_cache`: 3× `(B_bucket, H_bucket, 8, 128, 16)` (exact because `multihead_attn1` masked `t >= n_train` with `train_attn_mask` and `log_n_train`).
    - `icl_cache`: 12× `(B_bucket, 8, T_train_bucket, 64)` alongside cached `train_attn_mask` `(1, 1, 1, T_train_bucket)`, `log_n_train` `(1, 1)`, and `feat_attn_mask` `(1, 1, 1, 4 + H_bucket)`.
- **`predict(X_test)` (Cached Test Decode)**:
  - Bucket `n_test` to `T_test_bucket` in `{64, 256, 1024, 4096, 16384, 65536}` using the same `(B_bucket, H_bucket)`.
  - Run `ColEmbedding` (`multihead_attn2` only, reading `col_cache`), `RowInteraction` (masked by `feat_attn_mask`), and `ICLearning` (queries `T_test_bucket` attending to cached `T_train_bucket` K/V masked by `train_attn_mask` + `log_n_train`), then slice `[:B_real, :n_test, :num_classes]`.
